# dsh-etf-monitor

> DeepSeek Harness 侧边栏面板：盯住国家队最可能出手的 **15 只宽基 / 行业 ETF**，
> 盘中每 60 秒重算量比、护盘脉冲、溢价率与超额。
> 纯 Node 直取公开行情，**零第三方依赖、不读本地文件、不需要任何 API Key**。

## 它回答一个问题

盘中想知道「国家队/汇金是不是在买宽基 ETF」，看指数没用——指数会被权重股掩盖。
真正有信息量的是 ETF 自己的成交数据：**成交额有没有异常放大、是不是脉冲式护盘、
有没有一级申购资金顶着溢价买**。

面板把这三件事做成一屏读数，交易时段内自动重算。

| 你原本要问 | 面板给的读数 |
|---|---|
| 今天量放大了吗？ | 510300 量比推定 + 近 8 日成交额柱 |
| 是护盘还是换手？ | 护盘脉冲次数与明细（单分钟 ≥ 当日均量 4 倍） |
| 资金是在承接还是在出？ | 溢价率（对 IOPV）+ 主力净额 |
| 宽基和行业谁在动？ | 15 只篮子 + 行业/概念涨跌前列 + ETF 主力净流入流出 TOP |

## 面板长什么样

左侧图标栏（`sidebar.panellist`，order 30，排在「灵枢/上下文」与「梦境」之间），
图标名 **国家队ETF**。点开是 `main` 槽位的整页看板，四个区块：

1. **四项判读** — 510300 量比推定 / 护盘脉冲次数 / 溢价率 / 涨跌家数
2. **15 只 ETF 篮子** — 现价、涨跌幅、成交额、量比推定、主力净额、超额、溢价率
3. **510300 分时结构** — 半小时一桶，成交额柱 + 价位点，一眼看出是否脉冲式护盘
4. **市场宽度** — 主要指数 / 海外市场 / 行业与概念涨跌前列 / 全市场 ETF 主力净流入流出 TOP

## 读数怎么读

| 读数 | 定义 | 怎么判断 |
|---|---|---|
| 量比推定 | 当前成交额 ÷ 按已过交易分钟线性外推的全天成交额 | > 1.5× 才算真放量；< 0.7× 是缩量 |
| 护盘脉冲 | 单分钟成交额 ≥ 当日已过均量的 4 倍 | 连续出现 = 主动买；只出现一两次且价格被吞 = 试盘 |
| 溢价率 | ETF 市价相对 IOPV | 持续正溢价 = 有申购资金在顶；负溢价 = 折价没人接 |
| 超额 | ETF 涨跌幅 − 跟踪指数涨跌幅 | 只看同一只的时间序列，**不要跨标的横比** |

**最有用的一条组合判据**：成交额放大 **且** 溢价率转正 **且** 分时桶价格重心上移
——三条同时成立才是真护盘；只有第一条放大，往往只是「换手不是承接」。

## 安全与隐私

- **零第三方依赖**：只用 Node ≥ 18.17 内置的 `fetch` / `TextDecoder` / `AbortSignal.timeout`
- **不读本地任何文件**、不写任何文件
- **不需要 API Key、不需要账号**
- 只对 `push2.eastmoney.com`、`qt.gtimg.cn` 等**公开行情接口发 GET**，不携带任何个人数据
- 进程内 45 秒缓存，避免重复打上游

## 兼容性

| 项 | 要求 |
|---|---|
| DSH | 支持 `dsh.bundle.patch` 的版本（本包同时声明 `dsh.bundle` 与 `dsh.client`） |
| Node | ≥ 18.17（宿主自带 Node 即可） |
| 平台 | `web` 客户端（`dsh.client.platform: web`） |

## 接口

| 路径 | 说明 |
|---|---|
| `GET /dsh-etf-monitor/api` | 取快照，45 秒进程内缓存 |
| `GET /dsh-etf-monitor/api?fresh=1` | 强制重算 |
| `GET /dsh-etf-monitor/health` | 引擎、版本、最近一轮耗时、最近一次失败原因 |
| `GET /dsh-etf-monitor/debug` | 逐接口探活（排障用） |

也可以单独 import 数据层，不需要 DSH 运行时：

```js
import { takeSnapshot, summarize } from 'dsh-etf-monitor/snapshot'

const snap = await takeSnapshot()
console.log(summarize(snap))   // 状态=交易中 已过分钟=190 510300=4.18 (+2.2%) 成交额=113.0亿
```

## 口径局限（页脚也写了）

1. **量比是推定值**：用「已过交易分钟线性外推」估全天，开盘初期波动大，只看方向不看绝对值。
2. **超额含昨日溢价残留**：`ETF 涨跌幅 − 跟踪指数涨跌幅` 是代理指标，不可跨标的横比，只看同一只的时间序列。
3. **溢价率取腾讯 IOPV 字段**（`qt.gtimg.cn` 第 78 项）。东财的 `f71` 是**均价**不是 IOPV，早期版本在这里算错过。

## 数据源踩过的坑（改代码前先看）

1. 东财 `ulist.np` **并发十几条会整批返回空**（HTTP 200 但 `data.diff` 缺失）。现按 20 个一批切块，缺失的再逐个单发补齐，最多补两轮。
2. 涨停池的总数在 `data.tc`，不是 `data.total`；不带 `dpt=wz.ztzt` 会返回 `rc:102`。
3. 日线接口必须带 `end=20500101`，否则 `rc:102`。
4. 涨跌家数只能走 `ulist.np` 的 `f104/f105/f106`；`stock/get` 对指数返回 `"-"`。
5. ETF 跟踪指数的 secid 必须和 ETF 自己的 secid 一起请求，否则超额列全空。
6. 腾讯接口返回 GBK，用 `new TextDecoder('gbk')` 解，不要引 iconv。

## 改完怎么生效

- 改 `client.js`：**刷新一次页面**（客户端 bundle 是页面加载时取的，光切面板不重读）。
- 改 `lib/index.js` / `lib/snapshot.js`：宿主半侧热装配；不生效就把插件 disable 再 enable 一次。

## FAQ

**非交易时段显示什么？** 显示 `盘前` / `已收盘`，数据停在最后一个交易日的收盘值，不会报错也不会装成实时。

**数据延迟多少？** 东财与腾讯的免费行情普遍有 1–3 秒延迟，面板 60 秒刷新一次，不是逐笔。

**为什么不直接读指数？** 指数是加权结果，权重股的涨跌会盖住 ETF 自己的资金行为；护盘往往只体现在宽基 ETF 的成交结构和溢价上。

**能加自己的 ETF 吗？** 能，`lib/snapshot.js` 里的 `ETF_LIST` 加一条即可，注意异步补齐规则见「数据源踩过的坑」。
